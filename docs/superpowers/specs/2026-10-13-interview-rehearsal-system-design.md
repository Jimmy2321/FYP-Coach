# AI 面试排练系统 — 设计文档

> 项目名称：Interview Rehearsal System  
> 日期：2026-10-13  
> 所属计划：AI Venture Studio  
> 状态：设计中

---

## 一、项目动机（Why）

### 1.1 问题背景

每个毕业生在毕业后都面临两道关卡：

1. **技术面试**（求职路径）：编程思路题、系统设计、行为面试
2. **研究生申请**（深造路径）：学术面试 + 个人陈述

现有市场工具在这两个领域存在明显的断层：

- **面试准备工具**（Yoodli、Big Interview、Final Round AI）只关注面试表达，且大多收费、面向职场跳槽者而非应届毕业生
- **文书评审工具**（CollegeVine、Grammarly、I'mAdmitted）只管文书写作，不管面试
- **没有任何一款产品同时覆盖面试排练和个人陈述评审**
- 通用 AI（ChatGPT）可以两者兼顾，但缺乏结构化评分标准，输出不稳定，且没有面向学生群体的定制化设计

### 1.2 为什么值得做

1. **填补市场空白**：没有竞品同时覆盖技术面试排练 + 个人陈述评审，这是一个真实的市场缺口
2. **面向被忽视的用户群体**：主流面试工具面向有工作经验的跳槽者，毕业生群体的需求被严重忽视
3. **学术可行性已验证**：多篇 2025-2026 年的学术论文已证明 AI 辅助面试评分的技术可行性
4. **真实用户可触达**：作为学生，可以直接招集同学进行用户测试，这是商业产品无法做到的
5. **AI Venture Studio 支持**：有导师群组指导和年底展示会，提供学术背书和展示机会

## 二、项目范围（What）

### 2.1 核心功能（MVP）

| 模块 | 描述 | 优先级 |
|------|------|--------|
| 面试出题 | 支持行为题、编程思路题、学术面试题三种类型 | P0 |
| 答题输入 | 文字输入 + 语音输入（Web Speech API，可降级为纯文字） | P0 |
| 三维评分 | 纯 LLM 单次评分：正确性 + 结构 + 沟通表达 | P0 |
| 反馈报告 | 逐维度评分 + 具体改进建议 | P0 |
| 练习历史 | SQLite 存储历史记录，可回看和对比进步 | P0 |

### 2.2 扩展功能

| 模块 | 描述 | 优先级 |
|------|------|--------|
| 个人陈述评审 | 对比招生标准给出结构化反馈 | P1 |
| 题型/难度选择 | 用户可以选择面试类型和难度 | P1 |
| 评分趋势分析 | 展示多次练习的进步曲线 | P2 |

### 2.3 明确不做

| 功能 | 原因 |
|------|------|
| 代码运行环境 | LeetCode/HackerRank 已做得很好，且不是本项目核心价值 |
| 视频体态分析 | Yoodli/Big Interview 的领域，技术复杂度过高 |
| 实时面试辅助 | Final Round AI 的领域，涉及伦理问题 |
| 人工面试官匹配 | Interviewing.io/Pramp 的领域，运营成本高 |

### 3.3 数据流：一次面试排练的完整流程

```
1. 用户选择面试类型（行为题/编程题/学术题）和难度
         │
         ▼
2. 出题 API → 调用 LLM 生成一道题目
         │  （题目存入数据库，可复用）
         ▼
3. 用户界面显示题目
         │
         ▼
4. 用户用文字或语音回答
   （语音通过 Web Speech API 转为文字，用户可编辑）
         │
         ▼
5. 评分 API → 调用 LLM 按三维评分标准评分
   （prompt 包含：题目、标准答案要点、学生回答、评分 rubric）
         │
         ▼
6. 返回评分结果：三维分数 + 逐条反馈
         │
         ▼
7. 结果存入 SQLite，用户界面显示报告
         │
         ▼
8. 用户可查看历史记录和进步趋势
```

### 3.4 评分引擎详细设计

#### 评分维度定义

| 维度 | 定义 | 评分依据 |
|------|------|----------|
| 正确性 (Correctness) | 回答是否覆盖关键要点，技术/事实是否准确 | 对比标准答案要点的覆盖程度 |
| 结构 (Structure) | 回答是否有逻辑层次，是否使用清晰框架（如 STAR） | 逻辑连贯性、层次分明度 |
| 沟通 (Communication) | 表达是否清晰简洁，术语使用是否恰当 | 简洁度、准确性、可理解性 |

#### LLM 评分 Prompt 结构

```
系统角色：你是一位经验丰富的面试评分官。

输入：
- 面试题目：{question}
- 题目类型：{type}（行为题/编程思路题/学术面试题）
- 标准答案要点：{key_points}
- 学生回答：{student_answer}

评分标准（每维度 0-100 分）：
1. 正确性：学生回答是否覆盖了标准答案的各个要点，技术/事实是否正确
2. 结构：回答是否有清晰的开头-展开-总结，是否使用了适当的逻辑框架
3. 沟通：表达是否清晰简洁，术语使用是否准确，是否有逻辑跳跃

输出格式（JSON）：
{
  "correctness": {"score": 数字, "feedback": "具体反馈"},
  "structure": {"score": 数字, "feedback": "具体反馈"},
  "communication": {"score": 数字, "feedback": "具体反馈"},
  "overall_feedback": "总体建议"
}

参数：temperature = 0（确保评分稳定性）
```

#### 题库设计

每种面试类型预置一组标准题目，每题附带：
- 题目文本
- 题目类型
- 难度等级（简单/中等/困难）
- 标准答案要点（用于评分对比）
- 评分侧重点提示（不同题型的三维权重可能不同）

| 题型 | 正确性权重 | 结构权重 | 沟通权重 | 示例 |
|------|-----------|---------|---------|------|
| 行为题 | 40% | 35% | 25% | "描述你遇到过的最大技术挑战" |
| 编程思路题 | 50% | 30% | 20% | "如何设计一个短链接服务？" |
| 学术面试题 | 45% | 30% | 25% | "你为什么想读这个方向的研究生？" |

### 3.5 个人陈述评审设计（扩展功能）

#### 评审流程

```
1. 用户上传/粘贴个人陈述草稿
         │
         ▼
2. 用户选择目标项目类型（硕士/博士/具体领域）
         │
         ▼
3. 评审 API → 调用 LLM 按招生标准评审
   （prompt 包含：草稿全文、目标项目类型、招生评审标准）
         │
         ▼
4. 返回结构化评审报告
```

#### 评审维度

| 维度 | 定义 |
|------|------|
| 个人特质突出度 | 是否展示了独特的个人经历和品质 |
| 叙事连贯性 | 是否有清晰的叙事线，而非经历堆砌 |
| 学术匹配度 | 是否与目标项目/方向匹配 |
| 语言质量 | 语法、用词、表达力 |
| 结构完整性 | 开头-主体-结尾是否完整有力 |

### 3.7 语音输入方案

```typescript
// 使用浏览器原生 Web Speech API
const recognition = new SpeechRecognition();
recognition.lang = 'zh-CN'; // 或 'en-US'
recognition.continuous = true;
recognition.interimResults = true;

recognition.onresult = (event) => {
  // 实时显示识别结果
  // 用户可编辑后提交
};

recognition.onerror = (event) => {
  // 降级为纯文字输入
};
```

- 支持 Chrome 和 Safari
- Firefox 不支持时自动降级为纯文字
- 识别结果可编辑，确保用户对最终提交内容有控制权

### 3.8 错误处理

| 场景 | 处理方式 |
|------|----------|
| LLM API 超时 | 重试 1 次，仍失败则提示用户重新提交 |
| LLM 返回格式异常 | 解析失败时使用正则提取分数，或提示重新评分 |
| 语音识别失败 | 自动降级为文字输入 |
| 数据库写入失败 | 前端保留答案副本，提示用户稍后查看 |

| Google Interview Warmup | Yes | No | No | No | Yes | No |

| Big Interview | Yes | No | 部分 | 部分 | $39/月 | No |
| Interviewing.io | Yes | No | 人工 | No | $179/次 | No |

| Pramp | Yes | No | 同伴 | No | Yes | No |

### 4.2 核心竞争优势（客观评估）

#### 优势 1：唯一覆盖"双关"的整合平台

**事实**：在调研的所有商业产品中，没有任何一款同时覆盖技术面试排练和个人陈述评审。面试工具（Yoodli、Big Interview 等）和文书工具（CollegeVine、I'mAdmitted）是完全分开的市场。

**客观性说明**：这个优势的主要价值在于"整合"本身，而非功能深度。如果用户只需要面试排练或只需要文书评审，专门的商业产品在各自领域可能做得更深更好。本项目的优势在于为同时面临两关的毕业生提供了一站式体验。

#### 优势 2：三维度评分模型

**事实**：大多数面试工具的评分是单维度的——Yoodli 只评表达节奏（语速、填充词），Resumly 只给一个 0-100 总分。本项目将评分拆分为正确性、结构、沟通三个独立维度。

**客观性说明**：三维评分比单维度更有信息量，但评分质量高度依赖 LLM 的判断力和 prompt 设计。商业产品不做多维度评分可能不是因为做不到，而是因为对它们的目标用户来说单维度够用了。此外，纯 LLM 评分的稳定性和一致性不如基于规则的评分系统。

#### 优势 3：面向毕业生群体的定制化

**事实**：主流面试工具面向有工作经验的跳槽者，题库和评分标准都是职场导向的。本项目针对毕业生的特定场景——求职技术面试 + 研究生申请——设计题目和评分标准。

**客观性说明**：这个优势的持续性取决于目标用户的规模。毕业生群体虽然庞大，但每个用户使用周期短（毕业季几个月），用户留存率天然较低。商业产品不深耕这个群体可能正是因为 LTV（生命周期价值）不够高。

#### 优势 4：评分标准透明可审计

**事实**：作为学术项目，评分标准（三维 rubric 和权重）是公开的，用户知道每个分数的依据。商业产品的评分算法是黑箱。

**客观性说明**：透明性在学术环境中是优势，但在商业环境中可能是劣势——公开的评分标准容易被复制。此外，评分透明不等于评分准确。

#### 优势 5：真实用户验证

**事实**：可以直接招集准备真实面试的同学进行用户测试，收集真实反馈迭代改进。

**客观性说明**：同学测试的样本量有限（可能只有 5-15 人），且同学可能出于人情给出偏正面的反馈，影响数据的客观性。需要设计合适的测试方法来缓解这个问题。

#### 优势 6：学术背书与社区支持

**事实**：属于 AI Venture Studio，有导师指导、共享工具、年底展示会。

**客观性说明**：学术背书增加可信度，但不等于产品成熟度。学术项目通常在工程化、稳定性、可扩展性方面不如商业产品。

### 4.3 客观劣势评估

#### 劣势 1：功能丰富度不足

**事实**：不包含视频体态分析（Yoodli、Big Interview 有）、代码运行环境（LeetCode 有）、实时面试辅助（Final Round AI 有）、人工面试官匹配（Interviewing.io 有）。

**影响**：在这些特定功能维度上无法与专业产品竞争。但根据项目范围定义，这些功能被有意排除，因为不是本项目的核心价值。

**缓解策略**：在答辩和展示中明确说明范围边界，强调"做精而非做多"。

#### 劣势 2：LLM 评分的随机性

**事实**：纯 LLM 评分存在输出不稳定的问题——同一个答案在不同时间评分可能得到不同分数。

**影响**：评分可信度受质疑时难以自证。答辩时可能被问"你怎么保证评分的一致性？"

**缓解策略**：
- 设置 temperature=0 降低随机性
- 在文档中记录"语义相似度 + LLM"作为 future work 的改进方向
- 在用户测试中收集评分一致性数据（同一答案评 3 次看方差）

#### 劣势 3：题库规模有限

**事实**：预置题库无法与 Big Interview 的大规模题库或 LeetCode 的题量相比。

**影响**：用户练习几次后可能遇到重复题目。

**缓解策略**：
- 出题 API 可以用 LLM 动态生成新题目（而非仅从预置题库抽取）
- 在文档中说明题库设计支持动态扩展

#### 劣势 4：缺乏行业数据支撑

**事实**：商业产品如 Interviewing.io 有真实企业面试官的反馈数据，Big Interview 有 700+ 合作院校的使用数据。本项目从零开始，没有行业基准数据。

**影响**：评分标准的准确性缺乏外部验证。

**缓解策略**：
- 通过同学用户测试收集"AI 评分 vs 真实面试结果"的对比数据
- 在答辩中说明这是初步验证，承认需要更大规模的数据来校准

#### 劣势 5：用户留存天然较低

**事实**：毕业生群体的使用周期短（几个月），不像职场跳槽者可能反复使用。

**影响**：不适合做需要长期用户留存的产品策略。

**缓解策略**：不追求用户留存，定位为"一次性工具"——在毕业生最需要的时候提供价值，用完即可。

#### 劣势 6：工程成熟度

**事实**：作为学生项目，在性能优化、错误恢复、大规模并发处理、安全防护等方面不如商业产品。

**影响**：不适合大规模商用，但作为概念验证和学术成果完全够用。

**缓解策略**：明确项目定位为"学术原型"而非"商业产品"。

### 4.4 竞争力总结

| 维度 | 评价 |
|------|------|
| 功能广度（面试+文书） | **领先**，无直接竞品 |
| 评分深度（三维评分） | **有优势**，但稳定性待验证 |
| 用户群体匹配度 | **有优势**，面向被忽视的毕业生群体 |
| 功能丰富度 | **劣势**，明确排除多个功能领域 |
| 评分稳定性 | **劣势**，纯 LLM 评分有随机性 |
| 题库规模 | **劣势**，但可通过 LLM 动态出题缓解 |
| 工程成熟度 | **劣势**，定位为学术原型 |
| 成本优势 | **有优势**，完全免费 |

**定位声明**：本项目不试图在功能丰富度或工程成熟度上与商业产品竞争。其核心竞争力在于：以毕业生为核心用户，用三维评分模型提供一站式面试排练和文书评审体验，通过真实用户验证评分体系的有效性。作为学术项目，其价值在于验证"AI 辅助面试评分"这个方向的可行性，而非成为商业产品。

## 五、评估与验证计划

### 5.1 用户测试方案

| 阶段 | 参与者 | 目标 | 方法 |
|------|--------|------|------|
| 内测 | 3-5 人 | 验证核心功能可用性 | 完成一次完整面试流程，收集 bug 反馈 |
| 评估测试 | 8-15 人 | 验证评分有效性 | 同学做模拟面试，对比 AI 评分与自我评估 |
| 展示准备 | 3-5 人 | 收集展示素材 | 录制使用过程和反馈视频 |

### 5.2 评估指标

| 指标 | 测量方法 | 目标 |
|------|----------|------|
| 评分一致性 | 同一答案评 3 次，计算标准差 | 标准差 < 10 分 |
| 评分相关度 | AI 评分与同学自评的 Spearman 相关系数 | r > 0.5 |
| 用户满意度 | 5 点 Likert 量表 | 平均 > 3.5 |
| 反馈有用性 | "反馈是否帮你发现了盲点？" | 80% 以上回答"是" |
| 系统可用性 | SUS (System Usability Scale) 问卷 | > 65 分 |

### 5.3 学术对标

本项目的方法论与以下学术研究对标：
- IJIRMPS (2025)：AI 面试评分系统，使用语义相似度 + 结构化评分 [$TRAE_REF](https://www.ijirmps.org/papers/2025/3/232543.pdf)
- IEEE ICISCoIS (2026)：RehearsalAI，AI 驱动的模拟面试平台 [$TRAE_REF](https://xplorestaging.ieee.org/document/11447753)
- arXiv (2026)：NYU Stern 的多 LLM 评分方案 [$TRAE_REF](https://arxiv.org/html/2603.18221v2)

## 六、风险与缓解

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|----------|
| LLM 评分不稳定 | 中 | 高 | temperature=0 + 多次取平均作为 future work |
| 题目质量不均 | 中 | 中 | 预置题库经人工审核 + LLM 生成后抽样检查 |
| 用户测试样本不足 | 高 | 中 | 接受样本量限制，定位为初步验证 |
| API 成本超预算 | 低 | 中 | 使用 GPT-4o-mini（$0.0035/次），控制月度调用上限 |
| 语音识别准确率低 | 中 | 低 | 降级为纯文字，用户可编辑识别结果 |
| 答辩质疑评分可靠性 | 中 | 高 | 收集一致性数据 + 文献支撑 + 说明 future work |
